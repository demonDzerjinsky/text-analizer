## Задача 
библиотека реализующая API поиска N наиболее часто встречаемых слов в текстовых файлах в определенном каталоге с заданной минимальной длиной L. 
по условию задачи - обработка текста должна производиться в многопоточном режиме на пуле потоков, реализованном самостоятельно на основе низкоуровневых Threads.
### общее описание контракта библиотеки
- входной точкой для вызова методов api библиотеки является класс Reports
- демонстрация вызова api построения отчета по ТОП-10 наиболее часто встречаемых слов находится в тесте FindTopIntegrationTest::checkTop10() (см раздел - сборка проекта с запуском тестов)
- в запросе api построения отчета предусмотрен входящий контракт ReportTopRequestDto и ответ ReportTopResultDto
- детальное описание всех классов можно получить в документации после запуска генератора (см раздел - генерация документации по классам)
### сборка проекта с запуском тестов
```sh
mvn clean test
```
### генерация документации по классам 
```sh
mvn javadoc:javadoc
```
после генерации документация находится в 
```sh
${project_dir}/target/reports/apidocs/index.html
```
### подходы в проекте
- увеличение общей производительности обработки - параллельная обработка текстовых строк на самописном пуле потоков с независимым формированием статистики слов и последущим "мержем"
- потоковый + реакивноый подход к организации буферизированного чтения продьюсером и пулом потоков-обработчиков позволяющий сбалансировать работу компонентов, читать блоки с учетом общей производительности потребителей (пула потоков обработки) без необходимости повышенного потребления памяти хипа под буфферные структуры
- снижение нагрузки на процессор и хип путем использования мутабельного счетчика
- снижение вычислительной сложности алгоритма формирования ТОП слов через кастомный алгорим, выпоняющий эту операцию без сортировки всей  статистики и за один проход
